# 安卓构建与发版

ChillPass 的 Windows 版与安卓版**消费同一份 Web 产物**（`dist/`），
安卓壳只是一个 WebView 宿主，不含业务代码。因此 Web 层改版时两个平台自动同步，
不需要为安卓单独改代码。

## 一、环境要求

安卓壳由 Capacitor 8 生成，工具链版本要求比较硬：

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | 22+ | Capacitor 8 要求 |
| **JDK** | **21** | Capacitor 8 / AGP 8.13 要求 Java 21，**JDK 17 不够** |
| Android SDK | platform 36 + build-tools 36 | `compileSdk`/`targetSdk` 均为 36 |
| Gradle | 8.14.3 | 由 `android/gradlew` 自动拉取 |

本机当前的实际安装位置（免管理员、解压即用）：

- JDK 21：`C:\Users\chenyuchong\dev\jdk-21`
- Android SDK：`C:\Users\chenyuchong\AppData\Local\Android\Sdk`
- Android Studio：`C:\Users\chenyuchong\dev\android-studio`

`JAVA_HOME` / `ANDROID_HOME` 已写入用户级环境变量。**已经打开的终端不会自动生效**，
新开一个终端，或在当前终端里显式设置：

```bash
export JAVA_HOME="C:\\Users\\chenyuchong\\dev\\jdk-21"
export ANDROID_HOME="C:\\Users\\chenyuchong\\AppData\\Local\\Android\\Sdk"
```

## 二、三个产物

同一个 GitHub Release、同一个 tag 下放三个文件：

| 文件 | 用途 | 更新方式 |
| --- | --- | --- |
| `ChillPass-Setup-<版本>.exe` | Windows 安装包 | `updater.ps1` 静默安装 |
| `dist.zip` | 安卓热更新资源包 | live-update 插件下载后热替换，**不重装 APK** |
| `ChillPass-<版本>.apk` | 安卓首次安装 | 只需装一次 |

版本号单一来源是根目录 `package.json`：

- Web 产物由 `vite.config.ts` 的 `define` 注入（`__APP_VERSION__`）
- 安卓由 `android/app/build.gradle` 读取，`versionName` = 版本号，`versionCode` = `major*10000 + minor*100 + patch`
- Windows 的 exe 版本信息由 `installer/build-sea.mjs` 读取

⚠️ **已知隐患**：`installer/installer.nsi` 与 `installer/app.cjs` 里的 `APP_VERSION`
目前仍是写死的字符串，构建脚本不会替换它们。发版时若忘记同步，Windows 端的
更新判断（`/api/checkForUpdates` 用的是 `app.cjs` 内的版本号）会和实际版本脱节。
建议后续把这两个值也改成一构建期注入。

## 三、发版步骤

改完代码、改好 `package.json` 的版本号之后：

```bash
# 1. 构建 Web 产物 + 同步进安卓工程
npm run android:sync

# 2. 出 release APK
npm run android:apk           # 产物：android/app/build/outputs/apk/release/app-release.apk

# 3. 出安卓热更新包
npm run android:bundle        # 产物：release/dist.zip

# 4. Windows 安装包走原有流程
powershell -File installer/build-installer.ps1
```

一条命令跑完 1-3：

```bash
npm run android:release
```

然后把 exe / dist.zip / apk 三个文件上传到同一个 Release。

### 安卓端更新是怎么生效的

前端 `checkForUpdates()` 在原生宿主下会去读 GitHub Release，找到 `dist.zip` 资产；
用户点「一键下载」时插件下载该 zip、切换资源包并重启 WebView —— 全过程不重新打包、
不重新安装，也不需要上架应用商店。

**边界**：只有 Web 层（HTML/CSS/JS/资源）能这样更新。如果改的是原生层
（加插件、改权限、换图标、动 `minSdk`），仍然必须重新出 APK 并让用户重装。

## 四、签名密钥

签名文件与口令**没有入库**，位于：

- `android/chillpass-release.keystore`
- `android/keystore.properties`（明文口令）

> 🔴 **务必单独备份这两个文件。** 安卓要求后续版本必须用同一签名密钥，
> 密钥丢失后将无法为已安装的应用推送更新，只能换包名重新发布。

## 五、安全加固（可选，建议）

live-update 插件支持对热更新包做完整性/签名校验。当前实现只按 URL 下载，
没有校验 checksum，因此如果 Release 资产被篡改，客户端会照单全收。加固方式：

1. 给 `dist.zip` 一并发布一个 sha256 文件；
2. `checkNativeUpdate()` 读取该值，下载时把 `checksum` 传给 `downloadBundle`。

## 六、移动端样式

### 目标设备参数（写移动端 CSS 前先看这里）

测试机（vivo V2111A）的实测参数：

| 项 | 值 | 影响 |
| --- | --- | --- |
| 物理分辨率 | 1080 × 2408 | — |
| 密度 | 480（dpr 3） | **CSS 视口宽仅 360px**，不是 390px |
| 系统字体缩放 | 1.12 | 文字比正常大 12%，等效布局压力约 321px |
| WebView | Chromium **83** | 见下方可用特性清单 |

因此移动端样式必须按 **360px 宽 + 文字放大** 来设计，验证时建议用 320px 视口复扫一遍。

### 该 WebView 不支持的 CSS 特性

Chromium 83 比想象中旧，以下写法在这个设备上**不生效**：

- `:has()`（需 105+）—— 不能用它做条件选择器，只能靠显式类名
- `100dvh`（需 108+）—— 会整条声明被丢弃，需保留 `100vh` 兜底
- flex `gap`（需 84+）—— 实测布局正常（ROM 可能有回填），但新代码尽量别只依赖它

### 已做的适配

- `src/App.module.css`、`src/components/layout/Sidebar.module.css`
  各有一个 `@media (max-width: 768px)` 块：内容占满、导航横过来落到底部标签栏。
- `src/styles/global.css` 里统一禁止按钮文字换行（`button { white-space: nowrap }`）。
  窄屏 + 字体放大时，中文标签会被逐字竖排、把药丸按钮撑成圆形。
  同时列出了一批**例外**——承载「标题 + 说明」「答题选项」等长文本的按钮恢复换行，
  否则文字会溢出被裁掉。新增这类按钮时要把它加进例外列表。
- 新手教程弹窗（`WelcomeModal`）与引导任务卡（`GuideCard`）在移动端改为**不透明**底色，
  并去除背景模糊：半透明 + 模糊会削弱正文对比度。

### 仍然欠缺的

各业务页面（首页卡片、闯关页、错题本、教师工作台）尚未逐页针对窄屏精修，
仅保证「不裁切、不溢出、不出现竖排文字」。有真实课程数据时的布局
（答题选项、课程卡片等）建议装上手机后逐页过一遍。

## 七、调试

```bash
# 预览 Web 产物（等价于安卓 WebView 里看到的内容，用来快速验证样式）
npm run build && npm run preview -- --port 4180

# 装到已连接的设备上（手机需在开发者选项里允许「USB 安装」并在弹窗中点确认）
adb install -r release/ChillPass-0.1.3.apk

# 看运行日志
adb logcat | grep -i -E "capacitor|chromium|chillpass"
```

用 Chrome/Edge 的 `chrome://inspect` 可以远程调试 WebView 里的页面，
排查白屏、CSP 拦截这类问题比看 logcat 直观。
